Buyer reconciliation

Use this view to match Stripe buyers, private contact inbox submissions, and the manual fulfillment log before sending files or follow-up questions.

Contact inbox

This uses the same `OPS_DASHBOARD_PASSWORD` check as `ops-contact-inbox.html`. Contact records are not stored unless you keep this page open.

CSV inputs

Use a Stripe export that includes buyer email, payment ID, product, payment status, and created or paid timestamps. The fulfillment file defaults to the `paid-kits/FIRST-BUYER-FULFILLMENT-LOG.csv` header.

Ready.

Load contact records and one or both CSV files to build the reconciliation view.

Matching rules

  • Stripe rows match fulfillment rows by `stripe_payment_id` first, then by buyer email.
  • Stripe rows match contact records by buyer email first, then by company name when email is missing.
  • Tagged self-audit replies remain visible even without a Stripe match so founder-vs-advisor signals can be reviewed before fulfillment.
  • Reference IDs from `/api/contact` stay attached to the matched record so follow-up or audit requests can be traced back to the inbox.

Expected columns

  • Stripe CSV: one of `customer_email`, `customer email`, or `email`; one of `id`, `payment_intent`, `payment intent`, or `charge id`; one of `product`, `description`, or `price`; one of `created`, `created utc`, `paid at`, or `date`.
  • Fulfillment CSV: the repo header from `paid-kits/FIRST-BUYER-FULFILLMENT-LOG.csv` including `stripe_payment_id`, `stripe_customer_email`, `stripe_product`, and `delivery_timestamp_utc`.
